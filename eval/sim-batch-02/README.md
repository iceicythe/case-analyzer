# sim-batch-02 · 冻结评测集

30 例场景合成数据 + 人工复核标签 + 首次自动评测冻结结果。**输入、标签、结果、生成器源码、独立校验预言机全部随包发布**，克隆仓库即可复验，不依赖维护者本机。

批次 `sim-batch-02`　生成 2026-10-15（种子 `20261015`）　Case 数 30　评测冻结 2026-10-15

## 1. 来源声明（先读这一节）

- 全部为**仿真数据**：脚本按预设场景公式生成四路日志，不是道路实车采集，也不是封闭场地实车采集。
- 标签 = 程序参考区间 + 人工复核，**非独立盲标**；结果仅说明本批表现，不能外推为真实路测成绩或闭环控制效果。
- `vehicle_state.csv` 的 `acceleration_mps2` 由车速相邻点后向差分派生，不是独立传感器测量，不能作为独立于车速的交叉验证证据。
- 导入来源类型为 `synthetic`；本包 `cases/` 内每个 Case 的 `source_metadata.json` 已如实写明。

## 3. 判定口径（SD-WINDOW-1.1）

- **严格事件**：0.5 s 窗口降幅 ≥ 1.0 m/s，且 ≥ 4 个下降间隔 ≥ 0.01，累计回升 ≤ 0.1。
- **候选粗筛**：降幅 ≥ 0.6，下降间隔 ≥ 3，回升 ≤ 0.2。
- **对齐容差**：0.15 s；事件内每个车辆采样点在容差内唯一匹配规划与控制行。
- 完整定义见仓库 [数据与事件约定](../../docs/DATA_FORMAT.md)。

## 4. 30 例覆盖什么

- **常规样本 seg_001–018**：高速跟车、旁车切入、红灯停车、限速下降、前车切出恢复、无减速阴性、滑行缓降阴性、回升不隔断、双事件、走走停停三事件、边界降幅恰 1.000 / 0.998（误报样本）等。
- **困难与边界样本 seg_019–030**：多目标同帧、跟踪 ID 重联、目标日志缺失、车辆采样缺口（事件内/外）、规划或控制日志缺失、规划时钟相位差半格、时钟偏移 0.14 s 容差边界、规划 5 Hz / 车辆 10 Hz、事件延伸至片段末尾。
- `seg_011`（0.998 m/s）是典型误报样本：粗筛报候选，严格口径不应算事件——用于检验工具不把候选当事件。

## 6. 独立复验

```bash
# 1) 核对发布包完整性（任选其一）
sha256sum -c SHA256SUMS                 # Linux / macOS / git-bash

# 2) 跑独立预言机：从最终 CSV 重算真值，与设计意图逐条比对（默认只读，
#    不写任何文件，只输出报告到 verify_report.txt 并在终端打印）
python verify.py

# 3) 需要重算标签时，显式写到独立目录——reference_labels/ 永不被自动写入
python verify.py --labels-out recomputed_labels --report recomputed_report.txt
```

预言机检查契约（0.1 s 网格 / 时间递增 / 列数 / 行数上限）、事件真值、候选判定、观察状态、对齐与链路、复现性六类，原始结论见 `verify_report.txt`（30/30 一致）。

> **只读是默认行为**：`reference_labels/` 是人工复核生效标签（`human_verified`），`verify.py` 不会删除或改写其中任何文件；重算产物（`constructive_truth`，明确标注"非人工标注"）只在 `--labels-out` 指定的目录产生。历史版本曾默认清空该目录重写，那是设计缺陷，不是特性。想对比两种口径，用 `--labels-out` 输出后自行 diff——`seg_023` 的人机分歧见第 5 节。

## 7. 首次自动评测结果（2026-10-15 冻结）

30 条全部保留；27 条计算事件指标（含 27 个参考事件）。seg_022 / 023 / 024 存在车辆采样缺口，按运行前约定单独评价质量处理，不计事件精确率与召回率，原始标签未改动。

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| 候选召回率 | 100.00%（27/27） | 所有可评分参考事件均被候选覆盖 |
| AI 自动确认精确率 | 100.00%（TP=26，FP=0） | 一对一匹配 IoU ≥ 0.5，候选覆盖 ≥ 0.9 |
| AI 自动确认召回率 | 96.30%（26/27） | FN=1：seg_030 贴片段边缘转人工，仍计未自动检出 |
| 错误自动拒绝 | 0 | seg_011 候选被排除，未误拒参考事件 |
| 自动处理覆盖率 | 86.67%（26/30） | 25 个确认候选 + 1 个排除候选 |
| 数据问题处理符合率 | 100%（3/3） | 缺口 Case 不自动确认、不调用模型 |
| 匹配事件边界误差 | 起止均 0 秒 | 26 个匹配事件；模型已有规则参考区间，不能解释为独立边界预测能力 |
| AI 排查调用有效结果 | 23/25（92%） | 2 次 API 失败，保留本地回退报告，未重刷 |
| 报告有用率 | 待人工评价（0/25） | 未自动填写评价；格式校验不等于建议正确率。评价材料包已随发布：见 [`human_review/`](human_review/README.md)（规则清单 vs AI 建议的三维对照、10 份选例、记录模板与局限声明），执行后在此行填写实测数字 |

三点必须连同数字一起读：

- **数据是合成的**：数字证明流程闭环与口径自洽，不能外推为真实路测成绩。
- **标签非盲标**：构造真值 + 人工复核；盲标复测需独立安排，且标签与预测严格分离（先冻结预测再回放标签）。
- **AI 价值未证明**：同门控下纯规则基线事件指标与 AI 方案相同（`results/baseline.json`）；本批尚未证明加入 AI 能提高事件检测效果。模型为 `deepseek-flash`，`reasoning_effort=low`，共 51 条已完成业务调用记录。

逐 Case 对账（TP/FP/FN 与候选状态）见 `results/metrics.md`；25 份已交付报告见 `results/report_records/`（含证据引用与"共同出现不证明因果"一类限定措辞）。

## 8. 用本仓库复跑全流程

```shell
python scripts/run_benchmark.py --dataset eval/sim-batch-02/cases --labels eval/sim-batch-02/reference_labels --runtime <临时目录> --reviewer <姓名> --source-type synthetic --source-name "sim-batch-02 复现"
```

- 规则筛选与导入不依赖模型；AI 复核与排查需要有效模型配置（见 [API 配置](../../docs/API_CONFIG.md)）。
- 复跑会产生新的运行目录，**只能称回归，不称独立测试**；首次自动成绩以本包 `results/` 为冻结版本。
- 失败或不合规的模型结果会保留在评测中，有失败候选时仍输出指标并以非零退出码结束。
