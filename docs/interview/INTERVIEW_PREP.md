# Case Analyzer：面试讲稿与问答

适用目标：Momenta AI 测试提效实习生。依据当前代码与 [项目复盘](PROJECT_REVIEW.md)，整理日期 2026-10-17。

下面是回答框架，不要求逐字背诵。将“我做了”调整为实际贡献；不能解释、没有亲自验证的部分，先学习再写进个人经历。

## 1. 三个时长的项目介绍

### 30 秒版本

> 我做的是一个智驾测试日志分析工作台，主要解决查找减速片段、整理多模块证据和写排查报告这些重复工作。它用规则筛候选，用大模型做受约束复核和人工分流，再生成有来源引用的检查清单，支持记录、导出和飞书提醒。我比较关注的是模型结果怎么校验、任务失败怎么恢复，以及如何通过独立标签评价工具效果。

### 90 秒版本

> 项目叫 Case Analyzer，输入是归一化的车辆、目标、规划和控制 CSV。起初我发现分析一个速度下降片段，需要先确认是否符合事件定义，再查规划和控制请求，最后整理证据和报告，流程中有不少重复操作。
>
> 我们先明确了项目内的减速事件口径，用宽松规则找候选，用严格窗口形成参考区间。大模型接收车速、加速度和来源证据，输出确认、排除或转人工，但最终要通过程序的结构、引用、区间和质量检查。确认事件后，再整理多模块证据，由模型从允许的检查项中选择排序。
>
> 工程上做了批量接入、持久后台队列、输入变化失效、分阶段重试和离线报告，最近又补了飞书合并通知与重启去重。最近一轮功能验证记录是 107 项自动化测试通过。业务上已经有冻结事件评测流程，但真实道路收益和 AI 相对纯规则的提升仍需要独立验证。我会把这些限制与功能成果一起说明。

### 3 分钟版本

按六步说，不要把所有文件名塞进介绍：

1. **问题，约 20 秒。** 测试分析要在日志、曲线、标注和文档之间切换，希望把重复整理交给工具。
2. **输入输出，约 20 秒。** 四类 CSV 和来源声明进入；输出事件处置、证据、检查清单、核查记录与离线报告。
3. **核心方法，约 50 秒。** 质量门—宽松候选—受约束复核—不确定转人工—确认后多模块排查。讲清事件现象与故障原因的区别。
4. **工程难点，约 40 秒。** 挑“请求期间数据变化”和“排查失败仅重试失败阶段”之一，说明指纹和检查点。
5. **一次踩坑，约 30 秒。** 例如“正常返回被计为成功”或“合法 JSON 仍能编造故障”，讲修复和回归测试。
6. **结果与局限，约 20 秒。** 已跑通的功能链路、测试记录；没有证据的业务提效不报数字，下一步做独立数据和消融。

## 2. 业务与事件口径：高频问题 1—10

### 1. 你这个项目到底解决什么问题？【必会】

**回答：** 它把测试日志中的事件筛选、证据整理、复核分流和交付放在一个工作台里。人工仍负责关键核查，但不用对每个 Case 都重复查文件、整理数字和复制报告。当前重点是可追溯的分析流程，实际节省多少时间需要对照测量。

**追问准备：** 举一个具体用户操作：“导入一批 Case，后台处理后只先看待人工与失败项，确认事件可以直接查看带行号的排查报告。”

### 2. 这里的事件是什么？正常制动也算吗？【必会】

**回答：** 当前目标是项目自定义的持续明显纵向减速现象，主要按速度窗口判断。正常跟车或制动也可能满足事件定义。先确认现象，才讨论原因和合理性。模型不能因为“看起来是正常制动”就排除已经达到数值条件的事件。

**不要说：** 检测到事件就表示系统存在异常或危险。

### 3. 为什么不能看到速度下降就标一个事件？

**回答：** 小幅波动、缓慢下滑和连续明显减速是不同现象。只看曲线形状没有一致边界，标注者容易各画各的。因此明确时间窗、降速量、下降间隔和允许回升，再把符合条件的窗口合并。这样才能重复计算，也才能比较预测和标签。

### 4. 一个 Case 取几个窗口？【必会】

**回答：** 不固定个数。按 0.1 秒采样逐点滑动 0.5 秒窗口，每窗 6 个点、5 个间隔。N 个点通常得到 N-5 个窗口，先逐窗判定，再合并成完整事件。人工核查整段 Case 和完整事件，不是只看模型挑的一窗。

**手算：** 10 个连续采样点有 5 个六点窗口；某个合并事件可以由多个窗口组成。

### 5. 宽松候选和严格参考为什么用两套门槛？【必会】

**回答：** 候选阶段希望覆盖值得复核的区域，允许一定误报；严格阶段定义最终现象。当前候选为 0.5 秒内至少下降 0.6 m/s、至少 3 个下降间隔、累计回升不超过 0.2 m/s；严格事件为下降至少 1.0 m/s、至少 4 个下降间隔、累计回升不超过 0.1 m/s。候选边界不直接等于事件边界。

**补充：** 阈值是项目口径，尚未通过独立道路数据证明最优。

### 6. 两个相邻区间什么时候合并？

**回答：** 重叠或相接先取并集；分离区间需要检查中间采样，间隔不能超过 0.5 秒，速度不能回升，端点仍有至少 0.01 m/s 的下降，质量检查也要通过。这样能连接同一持续下降中的短空隙，又避免只凭时间距离把两次事件拼起来。

**追问：** 连续三个区间按时间顺序传递合并；持续时间仍是最终 end-start。

### 7. 加速度为什么只作辅助？

**回答：** 事件定义已经基于车速固定了。加速度有来源和噪声问题，差分加速度是同一车速信息的变换，不是独立证据。辅助展示能帮助发现不一致，但不能临时改变事件门槛。缺失应保留未知，也不能当 0。

### 8. 为什么复核时不让模型看规划、控制和 TTC？【必会】

**回答：** 复核任务回答“是否满足减速事件定义、边界是否可确认”。规划和 TTC 主要解释原因或风险，过早加入可能让模型因为场景“合理”而否定客观现象。因此当前复核用车辆和来源证据，确认后再使用模块证据排查。这样也避免规划日志变化无谓触发事件重新复核。

### 9. `object_state` 是感知信号吗？

**回答：** 它可以承载感知或融合模块输出的目标状态简化表示，包含 ID、距离、相对速度等。但本项目没有原始图像、点云和完整跟踪链路，也不能仅凭一个 ID 确认规划实际选中的对象。目标缺失、低置信和多目标歧义都需要分别解释。

### 10. 这个工具能定位到哪个模块出了问题吗？【必会】

**回答：** 能提供模块相关的观测和下一步检查方向。例如车辆在减速，但规划/控制证据不完整，先补覆盖；请求都有时再比较时间趋势。当前近邻和统计不能证明因果，也没有足够的时钟同步、执行反馈和复现条件，所以不能自动认定某模块故障。

## 3. 大模型与证据：问题 11—20

### 11. 规则已经算出区间，为什么还用 AI？【最容易被追问】

**回答：** 这是当前架构需要正视的限制。自动确认必须匹配程序参考区间，模型不能独立发现或优化边界。现阶段它主要承担按证据复核、表达疑点、转人工和排查项排序。对于纯数值事件，规则直接执行可能已经足够；AI 是否降低人工负担、是否增加不必要拒判，要用同口径对照证明。

**继续追问“能不能去掉”：** 可以保留无模型的人工/本地报告路径，并设计规则直接执行基线。如果 AI 没有额外收益，就缩小它的使用范围，而不为使用模型强行增加调用。

### 12. 大模型可以直接修改事件边界吗？【必会】

**回答：** 当前自动模式不允许。确认区间必须完整匹配 strict_reference_intervals，程序逐端点按容差核对；不一致转人工。这样牺牲模型自由调整边界的能力，换取规则一致和可审计。人工经过完整核查可以保存区间，再显式关联到候选。

### 13. Prompt 怎么设计？

**回答：** 分事件复核和排查两套。复核 Prompt 写明事件定义、来源与边界条件、三类决策以及证据要求；排查 Prompt 给程序摘要和允许检查项，要求保持根因未知。都要求结构化 JSON，日志仅作为数据。关键业务约束还在本地校验，不能只依赖提示词。

**代码：** `candidate_decision.build_decision_prompt` 与 `event_investigation.build_investigation_prompt`。

### 14. JSON Schema 能防止模型幻觉吗？【必会】

**回答：** 能限制结构和已明确的值，不能自动判断所有自然语言真伪。`type:string` 仍允许编造；`const` 或枚举可以强制引用程序给定事实。项目对正式事实、区间和时间线说明用了更强约束，但事件复核部分自由建议仍有残余风险，不能说完全杜绝幻觉。

### 15. 讲一次你修过的 AI 输出问题。【推荐 STAR】

**回答：** 时间线说明原先检查序号和非空字符串，结构合法仍可能写“已确定控制器故障，延迟 999 秒”。后来把每条说明绑定当前 observation，程序提供允许文本，模型只能选用；保存重放与渲染也校验。回归测试分别注入错误结论、数值和错配序号。这个问题让我明确，结构化输出的约束强度要逐字段审查。

**个人贡献提醒：** 如代码由 AI 辅助生成，应如实说明自己如何理解和验收这次修改。

### 16. 为什么不按模型置信度大于 0.9 就自动通过？

**回答：** 自报置信度没有经过独立标定，不能代表正确概率。当前以来源、边界、引用和数值一致性作为确定性门槛，模型说高置信也不能绕过。以后若要用置信度，需要固定数据做校准，并看不同阈值下的风险和人工量。

### 17. `validated` 是不是表示业务正确？【必会】

**回答：** 不是同一个层次。review.status 表示模型请求和输出校验状态，disposition 表示最终分流。输出可以 validated，但因为 needs_human 或规则冲突而转人工。最终业务正确还需要参考标签，排查建议质量需要工程审阅。

### 18. 规划和控制日志是如何对齐的？

**回答：** 以事件内车辆采样点为参考，在已排序模块时间里做近邻匹配，当前相关配置的容差为 0.15 秒，保存偏差并识别重复时间或等距等歧义。没有匹配、字段缺失、歧义和有效分别计数。它没有完成时钟校准，不能把这个偏差直接解释成执行延迟。

**算法追问：** 单个参考点二分找近邻约 O(log M)，N 个点匹配约 O(N log M)，不含读取和排序成本。

### 19. 你的知识库是不是 RAG？

**回答：** 当前是轻量本地知识检索：目录里声明链路状态、目标状态和关键词，状态优先加分，再用词项交集排序，选相关手册生成检查依据。没有 embedding 或向量数据库。我会直接称为知识检索与检查清单；如果以后引入语义检索，需要用实际命中与引用质量证明收益。

### 20. 模型究竟读到了哪些数据？

**回答：** 事件阶段读候选车辆上下文、加速度及来源、数值规则和参考区间；排查阶段读程序从多模块算出的摘要、缺口、时间线和允许检查条件。排查请求没有重复发送完整原始行和逐点对齐。完整证据保留本地，所以不能说模型独立重新检查了全部原始日志。

## 4. Python 与工程可靠性：问题 21—30

### 21. 批量导入怎样保证一条坏数据不影响其他数据？【必会】

**回答：** 每条 Case 的文件读取、编码转换、载荷构造、校验和导入都在逐条异常隔离内，错误进入该条结果；健康条目继续。可选文件缺失作为 warning，不增加一个假 Case。汇总要把 invalid 和 error 都算进失败，冲突单列，并通过非零退出码支持脚本判断。

**例子：** 第一个文件不是 UTF-8，第二个正常，测试应看到一条失败、一条成功，而不是整个进程退出。

### 22. 如何识别重复导入和保护已有结果？

**回答：** 先按 Case ID，包括大小写冲突检查。只有文件集合、内容哈希和来源说明都相同，才视为相同内容跳过；同编号但内容或来源改变就冲突。CLI 保留 CRLF，避免同一文件经不同入口变换换行后出现假冲突。哈希不代表采集真实性。

### 23. 文件存储怎么保证事务？

**回答：** 当前不是数据库事务。导入在 staging 中准备，按顺序写数据、模板、来源登记和索引，普通异常进行补偿回滚；单文件用临时文件替换。能降低半写入和普通错误损坏，但跨文件断电恢复未全部验证。若并发和规模增长，会考虑把元数据、索引和状态纳入数据库事务。

### 24. 前端两个页面同时保存会怎样？

**回答：** 请求带它读取时的 expected revision 或记录指纹，服务端比较当前版本，不一致就返回冲突，保留已有记录并提示读取最新版本。这样可以避免旧页面覆盖新保存。浏览器草稿是本地编辑状态，不等同正式保存。

### 25. 输入改了，为什么旧 AI 结果不会继续生效？【必会】

**回答：** 结果绑定输入和规则等依赖的指纹。请求前核对当前指纹，模型返回后再计算一次，避免请求期间被修改；保存与读取也检查当前依赖。失配标 stale，要求重新核查。事件和排查的依赖不同，规划改动应影响排查，不应无谓影响仅看车辆的事件判断。

### 26. 后台任务是什么实现？为什么没用 Celery？

**回答：** 当前单机单人，使用单 worker、线程条件变量与 deque，加 JSON 队列状态落盘、文件锁和检查点。HTTP 线程不执行整个模型流程。这个规模暂时不需要消息中间件；若出现多用户并发、跨机器调度或长队列，再引入数据库/任务队列并设计租约和幂等。

**不要说：** 当前具有分布式调度和大规模并行吞吐。

### 27. 服务崩溃后如何恢复？【必会】

**回答：** 任务和 in-flight 信息先落盘。重启加载任务、扫描导入索引，已保存且有效的复核/报告作为检查点复用；复核成功但排查失败只补排查。如果中断时请求结果不明确且没有可用保存结果，会标失败要求显式重试，避免静默产生第二次调用。

### 28. 为什么既有自动重试，又说不能自动重跑？

**回答：** 层次不同。适配器对 429、部分临时服务错误、连接或超时等做有限退避重试，次数可观测；任务层对持久失败或进程中断的未知请求不无限重跑。两者都无法证明远端没有处理过请求，尤其重试计费需要如实说明。SDK 的隐式重试关闭，便于统一记录。

### 29. 模型 401、超时、输出截断分别怎么办？

**回答：** 401/402/403 属于需要处理权限、余额或认证的问题，暂停后续队列；超时按适配器有限重试后保留失败；长度截断作为不完整输出，不当成有效 JSON 结果。排查已先保存本地证据报告，模型失败时仍能查看证据，再明确重试失败阶段。

### 30. 记录了哪些调用指标？

**回答：** 当前有延迟、请求次数、重试次数、HTTP 状态、Token 等字段，是否有值取决于响应提供的信息。成本缺少可靠数据时保留未知，不把字段存在说成已经测出了成本优势。模型用本地配置/环境变量适配，业务层依赖 generate 接口，便于用 mock 做回归。

## 5. 评测与测试：问题 31—40

### 31. 你怎样验证事件识别好不好？【必会】

**回答：** 固定数据、事件口径和匹配规则，用独立参考标签分层评价。先看候选是否覆盖真值，再看自动确认 Precision、Recall、错误拒绝和转人工数量。当前候选覆盖阈值 0.9，事件一对一匹配 IoU 阈值 0.5，同时保留边界误差和质量排除原因。最终报告质量另外评。

### 32. 为什么不能简单按“预测与标签有重叠”计正确？

**回答：** 极宽预测容易碰到很多标签，重复预测也可能多领 TP。采用区间 IoU 衡量边界相似，并做最大数量的一对一匹配，一个标签和一个预测最多匹配一次。多余预测是 FP，未匹配真值是 FN。

**手算：** 真值 `[1,3]`、预测 `[1.5,3.5]`，交集 1.5 秒、并集 2.5 秒，IoU=0.6，可以达到当前阈值。若两个相同预测对应一个真值，最多一个 TP，另一个 FP。

### 33. 模型正确转人工，也要算漏报吗？【必会】

**回答：** 看评价对象。若评价自动确认 Recall，有效真值事件没有被自动确认匹配就计 FN，即使转人工符合产品设计。若评价候选覆盖，已经筛到就不属于候选漏筛。因此应同时报告自动质量、候选覆盖和人工负担，不能用“这是保守设计”删掉自动化的分母。

### 34. 冻结评测具体冻结了什么？【必会】

**回答：** 先固定预测快照、输入文件哈希和相关规则/资源，再回放参考标签并开启对照，避免读到标签后覆盖预测。新评测使用新运行目录，不覆盖旧批次。它是防止结果互相污染的工程措施，不能让已用于调参的样本变成独立测试集，也不能自动产生盲标。

### 35. 标注能否全部让另一个大模型做？

**回答：** 可以用来预标注或发现争议，但不能直接当作独立真值。尤其同一规则、相同生成数据或相近模型可能共有错误。正式小规模评价至少要有人按固定口径核查完整事件与负例，争议保留 uncertain；原因评价也要结合原始证据，不能用另一段顺耳的文字作答案。

### 36. 合成数据、仿真数据、真实道路数据如何使用？

**回答：** 公式合成便于构造边界和异常、验证代码；闭环仿真能测试指定场景下控制反馈和预设问题，但效果受仿真模型与场景覆盖影响；道路日志更接近真实采集，标签和允许使用范围仍需核对。三类都可以计算声明范围内的指标，结果应分开报告，不能把仿真成绩写成道路成绩。

**本项目：** 对话曾使用合成数据，并讨论用户提供的闭环仿真数据；当前没有足够可复核材料支撑新的道路效果声明。

### 37. 最终报告建议怎么评价？【必会】

**回答：** 分三项审阅：事实与引用能否回到原始证据、检查动作是否具体可执行、是否包含无依据因果结论。再看缺材料能否明确说明、排序是否有帮助。当前有独立报告评价接口，但事件评测脚本没有生成或审阅报告，明确输出 report_quality=not_evaluated，不能拿事件 Recall 证明建议正确率。

### 38. 107 项测试说明什么？【必会】

**回答：** 这是最近一轮功能回归的用例数量和通过情况。测试使用临时空间、公式样例和 mock 模型，覆盖接入、分流、保存冲突、输入变化、恢复、报告约束和通知等。它不表示代码覆盖率 107%、真实模型准确率或大规模可靠性。另有浏览器用例检查页面操作与通知重发。

**可举的测试：** 多目标标歧义而非无目标；控制日志缺失优先补覆盖；排查失败仅重试排查；通知重发不增加模型调用。

### 39. 你说提效，提升了多少？【必会】

**回答：** 当前能证明减少了必须手动触发和反复整理的步骤，还没有可靠的真实工作计时对照，所以不报百分比。下一步在相同任务和质量门槛下比较人工流程与工具辅助流程，测主动操作时间、总完成时间、返工和模型成本；处理样本熟悉度与任务难度差异，报告样本数及分布。

**进一步：** 可以按场景分组，采用不同人员/不同任务顺序或交叉设计，避免第二次看同一 Case 本来就更快而误算工具收益。

### 40. 如何证明 AI 的贡献？【必会】

**回答：** 对事件层比较“规则直接处置”和“规则+AI 复核”，保持质量门、阈值和测试集相同，比较正确率、误拒绝、转人工与成本。对排查层比较“程序默认检查顺序”和“AI 选择排序”，固定同一证据包，盲评事实、可执行性和完成任务时间。当前边界受规则锁定，不能把规则命中的收益都记到 AI 上。

## 6. 飞书：问题 41—45

### 41. 为什么不在模型任务里直接请求飞书？

**回答：** 飞书网络超时不应该拖住模型分析。任务结束先写入精简本地通知，独立线程读取后合并发送。分析线程仍有本地记录开销，但不等远程 HTTP。通知失败保留状态，只重发通知，不触发新的模型分析。

### 42. 飞书记录为什么用 SQLite，任务却用 JSON？

**回答：** 任务现阶段是单 worker 的结构化进度快照，JSON 直观且便于保存与排查。通知需要较多记录去重、状态查询、批量转 sending、显式重试和替代旧记录，SQLite 的唯一键和事务更方便。两者不是天然优劣；若状态规模增大，应评估统一元数据存储。

### 43. 如何避免通知重复？能保证恰好一次吗？【必会】

**回答：** 用任务身份、输入及结果内容形成持久去重键，相同恢复结果不重复发送，短时间记录合并。发送前状态变 sending，成功记录 sent。如果进程在远端接收后、保存成功前崩溃，重启只能标 unknown。没有端到端幂等协议就不能保证恰好一次，用户先查群再决定重发。

**边界：** 手动创建新任务可能生成新通知，这是预期的状态更新；重复错误超时也可能已经送达，不能盲目无限重发。

### 44. 签名与配置如何处理？

**回答：** Webhook 和签名密钥放在 Git 忽略的本地配置或环境变量，不进业务 Prompt 和网页状态。以时间戳、换行和密钥拼接作为 HMAC key，对空消息计算 SHA256 HMAC，再 Base64。关键词每条卡片都包含。发布脚本跳过本地配置，只放空模板；错误只保留安全的类型和状态码，防止原文回显令牌。

**代码边界：** 当前日常工作台在启动时读配置，修改后重启；命令行每次读取。

### 45. 群里别人点工作台链接能打开吗？能在飞书里复核吗？

**回答：** 默认链接是运行服务电脑的 127.0.0.1，别人电脑点击会访问自己的本机，不能直接使用。当前没有团队部署和飞书交互回调，只做群通知，复核仍在本地工作台。配置一个 workbench_url 只改变卡片链接，不会自动开放网络或提供鉴权。

## 7. 技术取舍、个人贡献与岗位：问题 46—50

### 46. 为什么用原生前端、标准库服务，不选完整框架？

**回答：** 当前重心是单机分析流程，页面规模和部署要求有限，原生前端与 Python 服务减少构建和环境依赖，方便直接启动与演示。代价是路由、状态和错误处理需要维护，不能据此宣称适合大型团队系统。将来如果业务复杂，再以权限、协作、组件复用和吞吐需求选择框架。

### 47. 项目最难的地方是什么？

**建议回答：** 我会选“让模型结果成为可受理的工作记录”。难点不只是 API 能返回，而是模型可能结构合法但内容不成立，输入可能请求期间变化，保存结果可能失败，人工和 AI 的状态又不同。解决方式是明确规则与证据边界、分层状态、请求前后指纹和可恢复检查点，再用异常样本回归验证。

**准备一个代码点：** `WorkbenchReviewStore.review` 如何区分 call_failed、needs_manual_review、validated、stale。

### 48. 这些代码是不是 AI 写的？你自己做了什么？【必须真实】

**回答框架：** 项目是在 AI 辅助下逐步实现的，AI 参与代码草稿、调试和文档。我参与了哪些需求与口径判断、哪些人工核查、哪些模块我能修改，需要按实际讲。例如我能解释为什么事件与原因分阶段、为何某候选需转人工，并从入口追到结果校验。不能讲清的模块我会明确说还在学习，不把生成代码量当成独立能力。

**准备证据：** 展示一次真实反馈、一次边界判断和一处能现场修改的小功能。不要虚构“手写全部模块”或“独立解决所有底层问题”。

### 49. 再给你两周，你优先做什么？

**回答：** 先固定一小批允许使用的独立数据和标签，明确开发/测试划分；跑规则与 AI 对照，定位质量、人工量和调用成本差异。然后对报告做独立工程审阅，补一次真实任务计时。若这些验证暴露存储或吞吐问题，再做架构改造。数据和评价可信度比继续堆按钮更有价值。

### 50. 为什么你适合这个岗位？

**回答框架：** 我是智能车辆工程背景，能把车辆现象、规划/控制请求和测试证据分开理解；项目让我练习了 Python 数据处理、模型 API、异常处理、评测和飞书集成。我的优势是愿意把模糊需求变成可验证的规则与流程。代码熟练度和独立数据验证仍在提升，我能用具体模块和演示说明当前能力。

**不要背空话：** 用一条完整 Case 和一次调试经历支持“学习能力强”。实习时长可按当前实际情况说明；此前计划可实习 6 个月。

## 8. 四个 STAR 故事，挑两件练熟

| 故事 | S/T：具体问题 | A：处理与取舍 | R：可证明的结果 |
|---|---|---|---|
| 批量导入异常隔离 | 一条坏编码导致后续 Case 都没处理 | 将文件读取纳入逐条异常保护，区分 warning 与失败 | 坏条目失败、健康条目继续，数量按 Case 计 |
| 正式模型说明约束 | 结构合法的文本仍编造故障和数值 | 同观测绑定允许文本，保存与渲染再次校验 | 恶意字段及错配说明被测试拒绝 |
| 评测成功计数 | 函数返回却存了调用失败，成功数虚高 | 按保存状态判断，失败保留，标记评测范围 | 失败运行保存执行明细并返回非零状态 |
| 飞书送达未知 | 通知超时/崩溃后无法确认远端是否收到 | 独立线程、持久状态、unknown、用户明确重发 | 重启不重复已发结果；重发通知不重跑模型 |

每个故事练到 60～90 秒：先说可复现现象，再说根因、修改位置、验证方式与剩余限制。只选择自己能解释代码的故事作为个人主讲。

## 9. 三道现场推演

### 推演 A：车速单调下降，但不够快

给定 0.5 秒六个点：`[20.0,19.85,19.70,19.55,19.40,19.25]`。

1. 首尾下降 0.75 m/s，5 个下降间隔，回升为 0。
2. 达到当前宽松候选门槛，未达到严格 1.0 m/s 门槛。
3. 没有严格参考事件时，模型可以在证据充分且路由门通过后排除当前候选。
4. 不能由此认定整段 Case 都没有事件；其他窗口还要检查。
5. 也不能依据“曲线很顺”临时改阈值。

### 推演 B：两个预测重复命中一个真值

真值只有 `[1,3]`，预测为 `[1,3]`、`[1.1,3.1]`。

1. 两个预测各自 IoU 都达标，但一对一只允许一个匹配。
2. TP=1、FP=1、FN=0；Precision=1/2，Recall=1。
3. 若把“每个预测只要重叠就算正确”，就会错算重复检测。
4. 若只剩转人工候选、没有自动确认预测，则自动 TP=0、FN=1；候选覆盖仍可达标。

### 推演 C：报告发出前后崩溃

1. 复核和排查结果已保存，通知状态 pending。
2. 独立线程改为 sending 并请求飞书。
3. 飞书已接收，进程在本地写 sent 前崩溃。
4. 重启只能知道上次是 sending，转 unknown，不能据此再次自动发送。
5. 用户确认重发仅重试通知，不重新生成报告、不重新调用模型。

## 10. 代码讲解演练

### 演练一：一条模型结果从请求到分流

按顺序打开 `workbench_reviews.py:review`、`candidate_decision.py`：

1. `expected_fingerprint` 防止什么旧请求？
2. `build_decision_prompt` 给哪些数据？
3. `adapter.generate` 返回 dict/string 后，在哪里做本地校验？
4. 为什么请求成功仍可能 needs_manual_review？
5. 返回后为什么重算 `_signature`？
6. `route_decision` 为什么再次检查来源、边界、证据和区间？
7. 临时文件替换保存了什么，读取时如何得到 disposition？

能画出以上链路，再谈“接入大模型”，就不会停留在调用 API 一行代码。

### 演练二：事件匹配

用纸写出以下伪代码，再解释真实实现为何用增广路径最大匹配：

```text
对每个预测区间：
    找出 IoU 达阈值的真值候选
通过一对一最大匹配选出配对
TP = 配对数
FP = 预测数 - TP
FN = 真值数 - TP
```

训练点：为什么只按预测顺序贪心领取第一个真值可能损失匹配数量？可查看 `test_matching_maximizes_number_and_does_not_double_count` 的反例。

### 演练三：现场小改动

选一个真正理解的练习，在隔离分支或副本完成，不修改当前正式运行数据：

- 调整一项页面状态说明，并解释它对应 review、disposition 还是 job。
- 给导入汇总新增一个已有统计的展示，不改变 Case 总数口径。
- 给一种模型失败补一个测试场景，证明不会自动重复成功阶段。
- 给通知卡片增加已有的计数，但不把原始 CSV 或密钥放进消息。

不要为了演示临时放宽质量门或删掉引用校验。

## 11. 约 7 分钟演示路线

### 演示前准备

```powershell
# 启动隔离的无模型演示空间；名称已有数据时换一个目录
```
