# 飞书通知

飞书用于接收工作进展与待办提醒。事件判断和人工确认仍在本地工作台完成，不支持在群里上传日志、对话查询或点击卡片修改复核结果。

## 配置

在飞书群的“设置 → 群机器人”添加自定义机器人，复制 Webhook。若启用关键词，设置为 `case-analyzer`；若启用签名校验，复制对应签名密钥。两者可同时启用，签名按[飞书官方文档](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)计算。

运行 `setup.cmd` 会创建 `configs/feishu.local.json`。已有项目也可将 [配置模板](../configs/feishu.example.json)复制为同目录下的 `feishu.local.json`，内容如下：

```json
{
  "enabled": true,
  "webhook_url": "在这里填写机器人的完整 HTTPS Webhook",
  "signing_secret": "",
  "keyword": "case-analyzer",
  "workbench_url": "",
  "summary_window_seconds": 5
}
```

- `enabled`：启用开关，模板默认关闭。填写 Webhook 后改为 `true`。
- `signing_secret`：开启飞书签名校验时必填，否则留空。
- `keyword`：每条卡片都包含该词，需要与机器人关键词设置一致。
- `workbench_url`：留空时使用当前服务实际端口的本机地址；本机链接只能在运行服务的电脑上使用。只有另行配置了可访问的部署入口时才填写该入口，填写地址不会改变本服务的监听范围或自动开放远程访问。
- `summary_window_seconds`：1～60 秒，默认 5。首条待发记录等待这段时间后，与期间产生的记录合并发送，每条最多 20 个 Case。

服务在启动时读取配置，修改后重启。命令行每次执行读取。也支持 `FEISHU_WEBHOOK_URL` 和 `FEISHU_SIGNING_SECRET` 环境变量；URL 优先级为 `--notify`、环境变量、本地文件。显式传入 URL 或设置非空 URL 环境变量会启用通知，即使文件中 `enabled` 为 false。改用另一 URL 时不会沿用文件中属于原机器人地址的签名密钥，应同时提供对应的签名环境变量。

本地配置已加入 Git 忽略规则。发布脚本不会读取本地密钥，只打包空配置模板；网页接口和通知记录不包含 Webhook 或签名密钥。

## 检查与试发

在项目根目录的 PowerShell 中执行：

```powershell
# 仅检查本地配置，不发送消息，也不调用模型
.\.venv\Scripts\python.exe -m app notify

# 向配置的飞书群发送一条连接测试
.\.venv\Scripts\python.exe -m app notify --test
```

测试成功后重启工作台。在自动模式下导入数据，后台会自动记录和推送处理结果。未配置模型、关闭自动队列或处于冻结评测空间时，不运行日常工作台通知队列；命令行通知仍可单独使用。

## 通知内容与触发时机

| 场景 | 行为 |
|---|---|
| 自动复核与排查结束 | 汇总 Case 数、确认区间数和已生成的 AI 排查报告数，附 Case 链接 |
| AI 不确定或数据质量不足 | 标为待人工复核或数据待核查 |
| 模型调用失败、输入改变 | 标为失败或变更；认证、余额、权限问题另提示队列暂停 |
| 无候选事件 | 自动处理结束，区间数和报告数为 0；不代表道路场景没有其他问题 |
| 人工确认后自动继续排查 | 后续任务结束时推送新结果 |
| 命令行批量导入 / 冻结事件评测 | 沿用原有导入汇总 / 指标卡片，共用本地配置、关键词和签名 |

卡片标题为“处理进展”，它统计本次通知中的更新，**不表示整批导入或所有后台任务已经完成**。卡片只包含编号、状态、计数和链接，不包含原始 CSV 或完整排查报告。报告生成也不表示故障根因已确认。

首次启用后，启动扫描会为已有 Case 当前可读取的处理结果建立通知记录。此后同一结果不会因为刷新页面、重复扫描或重启服务再次发送；新任务、输入指纹或处理结果变化可产生新通知。

## 失败、恢复与重发

工作台任务总览的 AI 队列下方显示一行飞书状态，数字按 Case 更新记录计数，不是卡片条数。只有发送失败或送达未知时才出现“重发通知”。重发只操作通知，不重新调用大模型。鼠标停留在状态文字上可查看最近的脱敏错误。

通知使用独立线程，网络故障不会阻塞模型队列。记录保存在 `runtime/model_reviews/feishu_notifications.sqlite3`，新建运行目录则使用该目录下同名位置：

- 已发送记录保留用于去重；未发送记录在重启后继续。
- 请求异常不自动循环重发。超时可能已经送达，点击重发前请检查群消息。
- 服务中断时正在发送的记录标为“送达未知”，等待人工决定是否重发，不能保证恰好送达一次。
- 同一 Case 出现新结果时，旧的待发送或失败记录会被替代，重发以新结果为准。
- 通知数据库不可读或无法写入时停止通知，工作台分析继续；检查磁盘及文件权限后重启，保留原文件排查。

配置检查通过只说明格式有效；签名、关键词、机器人权限及网络是否可用，需要通过 `notify --test` 验证。签名失败时检查密钥和电脑时间，关键词失败时核对 `keyword` 与机器人设置。
