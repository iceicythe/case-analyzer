# 如何评价效果

自动化测试和演示样例验证功能及约束。业务效果需另外准备允许使用的数据、独立参考标签和固定评价方案。本仓库不附带第三方道路日志、个人人工记录或历史实验结果。

## 建议固定的口径

| 对象 | 需要的参考 | 应报告的指标或结果 |
|---|---|---|
| 候选筛选 | 独立标注的事件区间 | 候选覆盖率、未覆盖事件和样本数量 |
| 自动确认 | 同一事件参考与预先声明的匹配阈值 | Precision、Recall、FP/FN、自动处理覆盖率、转人工数量 |
| 质量分流 | 已知缺口、边界和来源问题 | 是否保留待核查，是否错误自动确认 |
| 排查建议 | 对应原始证据及工程审阅 | 事实是否正确、引用能否定位、步骤能否执行、缺材料是否说明 |
| 工程调用 | 实际 API 返回和失败记录 | 有效输出率、延迟、Token、失败类型与重试次数 |

先冻结数据划分、事件定义和匹配阈值，再生成结果。不要用检测器输出或模型结论直接代替人工真值；已经据此改进过的场景应归为开发/回归集。

## 独立对照

保留纯规则基线，使用同样的数据质量与边缘处理口径。AI 与规则的检测成绩相同也应如实记录，不能因为用了大模型就宣称更准。

排查模型选择的是固定检查项，效果提升可能来自更好的取证、摘要或检查规则。应分别记录程序改进和模型排序的贡献。输出通过 schema 只是可用性，不是建议正确率。

## 失败与缺数据

模型失败保留首次状态及本地回退；重新运行使用独立批次。缺日志的 Case 保留待数据，不补造不可知的模块信号。人工评价未完成时，有用率保持未知。

演示 CSV 只有公式设计，没有独立场景真值或故障根因标签，因此不用于对外声称准确率。吞吐与运行稳定性也应在明确的机器、数据规模和持续时间下单独报告。

## 合成数据集可以怎么报告

由公式生成、但带逐段人工复核标签的数据集，可以按本文件口径报告成绩，前提是三条声明随数字一起发布：数据为合成场景而非真实道路采集；标签为构造真值经人工复核而非独立盲标；先冻结预测再回放标签。缺少任一条，数字只能作为内部回归参考。

`scripts/run_benchmark.py` 固化了这条链路：导入、AI 复核、冻结批次、回放标签、开启对照。数据质量门未过的 Case 按协议降级为数据不足，不进入指标分母；边界事件按设计转人工，不计入漏报。
